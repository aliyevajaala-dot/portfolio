# Prompt Journal

## Entry 1

### Prompt
“Mood əsaslı event tapma tətbiqi” üçün 3 ekranlı mobil app konsepti yaratmaq. İstifadəçinin hissinə və sosial vəziyyətinə görə uyğun event təklif edən flow dizayn etmək.

---

### Məqsəd
AI-dan sadə, real və emosional UX flow almaq. Məqsədim:
- mood-based qərar məntiqini görmək
- UI üçün uyğun mikrocopy əldə etmək
- strukturlaşdırılmış ekran axını yaratmaq

---

### Nəticə
AI 3 əsas ekrandan ibarət flow təqdim etdi:
1. Mood seçimi
2. Qısa emosional analiz
3. Event təklifləri

Flow ümumilikdə məntiqli idi və real mobil tətbiq hissi verirdi. Mətnlər qısa və UI üçün uyğun idi.

---

### Nə yaxşı idi
- Struktur aydın idi (3 ekran dəqiq verilib)
- Promptda rol düzgün seçilmişdi (UX designer + AI expert)
- Mətnin qısa və UI uyğun olması qeyd edildiyi üçün cavab daha istifadə edilə bilən oldu
- İstifadəçi yönümlü yanaşma qorundu

---

### Nə zəif idi
- Output format dəqiq verilməmişdi (AI cavabı bəzən qarışıq ola bilər)
- UI elementlərin sayı və strukturu göstərilməmişdi
- Vizual hierarchy və UX constraint-lər zəif idi
- Nəticə yaxşı olsa da, tam product-level deyil, daha çox konsept səviyyəsində qaldı

---

### Növbəti dəfə nəyi dəyişərdim
- Hər ekran üçün konkret struktur verərdim:
  - Screen name
  - UI elements
  - Microcopy
- Element sayını limitləyərdim (məsələn: max 2 seçim, 1 CTA)
- Daha konkret UX constraint əlavə edərdim
- Cavabın formatını əvvəlcədən təyin edərdim

---

### Öyrəndiyim dərs
Yaxşı prompt sadəcə nə istədiyini demək deyil. AI-ın verəcəyi cavabın strukturunu da dizayn etmək lazımdır. Əks halda nəticə yaxşı olsa da, dağınıq və tam istifadə edilə bilən olmur.

## Entry 2

### Prompt
Şəxsi portfolio üçün tam brend və dizayn sistemi təyin etmək:
- Brend adı, sloqan və təsvir
- Tone of voice və yazı qaydaları
- Rəng palitrası və istifadə qaydaları
- Tipoqrafiya sistemi və ölçülər
- Spacing, radius, kölgə
- UI komponent qaydaları (button, card, nav)
- Accessibility standartları

---

### Məqsəd
Portfolio üçün konsistent və peşəkar vizual və mətn sistemi qurmaq. Məqsədim dizayn və copy baxımından vahid dil yaratmaq və gələcək UI işlərini sürətləndirmək idi.

---

### Nəticə
AI bu məlumatlara əsaslanaraq daha sistemli və brendə uyğun dizayn və mətnlər yaratdı. UI elementlər arasında uyğunluq artdı və ümumi məhsul daha premium hiss etməyə başladı.

---

### Nə yaxşı idi
- Çox detallı və strukturlaşdırılmış input verilib
- Dizayn sistemi səviyyəsində düşünülüb (sadəcə ekran yox)
- Rəng, tipoqrafiya və komponentlər arasında konsistensiya var
- Accessibility və real məhsul qaydaları nəzərə alınıb
- Brend tonu və vizual dil aydın təyin olunub

---

### Nə zəif idi
- Bu promptda konkret task yoxdur (AI nə yaratmalıdır məlum deyil)
- Çox böyük və ağır inputdur (AI fokusunu itirə bilər)
- Prioritetlər göstərilməyib (nə daha vacibdir?)
- Output format yoxdur (nəticə strukturlaşdırılmamış ola bilər)
- Bu daha çox "design documentation"-dır, prompt deyil

---

### Növbəti dəfə nəyi dəyişərdim
- Bu sistemi konkret task ilə birləşdirərdim:
  - məsələn: “portfolio homepage dizayn et”
- Inputu hissələrə bölərdim (hamısını bir promptda verməzdim)
- Output format əlavə edərdim:
  - Section structure
  - UI elements
  - Copy
- Ən vacib qaydaları highlight edərdim (məsələn: primary color usage)

---

### Öyrəndiyim dərs
Detallı olmaq yaxşıdır, amma AI üçün effektiv prompt yaratmaq üçün bu detalları düzgün kontekstdə və konkret tapşırıqla birlikdə vermək lazımdır. Əks halda bu məlumatlar istifadə olunmur və ya zəif istifadə olunur.
Yaxşı prompt sadəcə nə istədiyini demək deyil. AI-ın verəcəyi cavabın strukturunu da dizayn etmək lazımdır. Əks halda nəticə yaxşı olsa da, dağınıq və tam istifadə edilə bilən olmur.

## Entry 3

### Prompt
"Nabz" adlı AI əsaslı mood-based event tövsiyə edən mobil tətbiqin tam funksional konseptini yaratmaq.
- 3 ekranlı UX flow (mood, analiz, tədbirlər)
- AI məntiqi və tövsiyə sistemi
- UI komponentləri (kartlar, buttonlar, navigation)
- Dark theme dizayn
- Gemini API inteqrasiyası və deployment tələbləri

---

### Məqsəd
AI-dan həm UX konsept, həm UI strukturu, həm də texniki implementasiya almaq. Məqsədim ideyanı konseptdən yarı real məhsul səviyyəsinə çatdırmaq idi.

---

### Nəticə
AI geniş cavab verdi:
- UX flow düzgün quruldu (3 ekran)
- Event kart strukturu detallı oldu
- AI məntiqi əsas səviyyədə işlənildi
- Texniki hissədə ümumi yanaşma təqdim olundu

Amma cavab çox geniş və qarışıq idi — UI, UX və texniki hissələr bir-birinə qarışdı.

---

### Nə yaxşı idi
- Task artıq konkret və real məhsula yaxındır
- UX flow + AI logic birlikdə düşünülüb
- UI elementləri detallı verilib (event kartı çox yaxşıdır)
- Texniki hissə əlavə edilməsi ideyanı gücləndirir
- Constraint-lər əvvəlkilərdən daha balanslıdır

---

### Nə zəif idi
- Scope çox genişdir (UX + UI + Backend + DevOps hamısı bir promptda)
- Output format yoxdur → cavab dağınıq olur
- Prioritet yoxdur (nə əsasdır: UX, UI yoxsa kod?)
- “Tam funksional” qeyri-real expectation yaradır
- Gemini API hissəsi çox səthidir və konkret deyil

---

### Növbəti dəfə nəyi dəyişərdim
- Promptu hissələrə bölərdim:
  1. UX flow
  2. UI design
  3. AI logic
  4. Texniki implementasiya
- Output format əlavə edərdim:
  - UX Flow
  - UI Components
  - AI Logic
  - Tech Architecture
- “Tam funksional” əvəzinə “prototype level” kimi daha real scope verərdim
- Texniki hissədə konkretlik artırardım (API request/response strukturu)

---

### Öyrəndiyim dərs
Bir promptda çox şey istəmək nəticəni zəiflədir. AI-dan maksimum nəticə almaq üçün problemi hissələrə bölmək və hər hissə üçün ayrıca, fokuslu prompt yazmaq daha effektivdir.

## Entry 4

### Prompt
Ev məhsulları mağazası üçün mobil tətbiq storefront ekranı dizayn etmək.
- Header (geri düyməsi + mağaza adı)
- Gradient banner və üzərində mağaza kartı
- 2 məhsul bölməsi (yorğanlar, yastıqlar)
- Horizontal scroll kartlar (3 visible)
- Məhsul kart strukturu (şəkil, ad, qiymət)
- Vizual stil və şəkil qaydaları
- Spacing və UI qaydaları

---

### Məqsəd
AI-dan real e-commerce tətbiqinə bənzər, istifadə edilə bilən və vizual olaraq konsistent storefront ekranı almaq.

---

### Nəticə
AI ümumilikdə düzgün struktur təqdim etdi:
- Layout məntiqli idi
- Məhsul kartları aydın təsvir olundu
- Vizual stil (minimal, açıq tonlar) qorundu

Amma bəzi hallarda nəticə yenə də “template hissi” verə bilər və ya dizayn kifayət qədər fərqlənməyə bilər.

---

### Nə yaxşı idi
- Struktur çox aydındır (header → banner → sections → cards)
- Vizual constraint-lər yaxşı verilib (rənglər, şəkil stili)
- “Real hiss etsin, template yox” kimi yönləndirmə düzgündür
- Spacing konkret verilib (16px → yaxşı qərardır)
- Kart strukturu kifayət qədər aydındır

---

### Nə zəif idi
- Output format yoxdur (UI necə təqdim olunacaq aydın deyil)
- Interaction yoxdur (hover, tap, state-lər göstərilməyib)
- Hierarchy tam açılmayıb (nə primary, nə secondarydir?)
- “Narıncı qiymət” var, amma brand consistency düşünülməyib
- UX məqsədi zəifdir (istifadəçi nə etmək istəyir?)

---

### Növbəti dəfə nəyi dəyişərdim
- Output format əlavə edərdim:
  - Screen structure
  - Component breakdown
  - UI copy
- Interaction-lar əlavə edərdim:
  - tap state
  - scroll davranışı
- UX məqsədi əlavə edərdim:
  - istifadəçi nə etmək üçün buradadır?
- Vizual prioritetləri təyin edərdim:
  - banner vs product cards hansı daha vacibdir?

---

### Öyrəndiyim dərs
Vizual detalları vermək yaxşıdır, amma real məhsul dizaynı üçün interaction, hierarchy və istifadəçi məqsədi də eyni dərəcədə vacibdir. Əks halda dizayn sadəcə gözəl görünür, amma UX baxımından zəif qalır.

## Entry 5

### Prompt
Event booking platforması üçün event details və ticket selection səhifəsi dizayn etmək.
- Dark theme, neon accent UI
- Hero, info, description, ticket selection bölmələri
- Seat map + ticket list + selection mode
- Interaction və UX prioritetləri
- Conversion-focused yanaşma

---

### Məqsəd
AI-dan yüksək səviyyəli, real məhsula yaxın, conversion yönümlü event və ticket seçimi təcrübəsi almaq. Məqsədim həm vizual keyfiyyət, həm də UX baxımından güclü ekran əldə etmək idi.

---

### Nəticə
AI strukturlaşdırılmış və detallı UI konsepti təqdim etdi:
- Bölmələr düzgün ayrıldı
- Ticket selection hissəsi yaxşı işlənildi
- UX prioritetləri müəyyən qədər qorundu

Amma nəticə yenə də tam “high-fidelity product design” səviyyəsinə çatmaya bilər və bəzi hissələr ümumi qalır.

---

### Nə yaxşı idi
- Struktur çox güclüdür (hero → info → selection → CTA)
- UX prioritetləri açıq şəkildə verilib (conversion focus)
- Ticket selection hissəsi çox yaxşı detallandırılıb
- Interaction-lar qeyd olunub (sticky CTA, transitions)
- Vizual stil aydın və fərqləndiricidir (neon + dark theme)

---

### Nə zəif idi
- Output format hələ də qeyri-dəqiqdir
- Responsive davranış qeyd olunmayıb (mobile vs tablet vs desktop)
- Real data constraint yoxdur (məsələn: neçə ticket göstərilməlidir)
- Edge case-lər yoxdur (sold out, error state və s.)
- Seat map hissəsi çox abstraktdır (real implementasiya çətindir)

---

### Növbəti dəfə nəyi dəyişərdim
- Output format əlavə edərdim:
  - Screen breakdown
  - Component states
  - Interaction flows
- Edge case-lər əlavə edərdim:
  - sold out
  - loading
  - error
- Responsive qaydaları əlavə edərdim
- Seat map üçün daha konkret constraint verərdim (grid, zones, colors)
- Data limitləri təyin edərdim (məsələn: max 6 ticket visible)

---

### Öyrəndiyim dərs
Yaxşı struktur və UX düşüncə kifayət deyil. Real məhsul səviyyəsinə çatmaq üçün edge case-lər, state-lər və konkret data constraint-lər də dizayn edilməlidir. Əks halda nəticə konsept olaraq qalır.
